`DouyinAuthenticatedClient` adapts the WebSocket handshake setup in OrdinaryRoad 1.5.8's `DouyinLiveChatClient.initConnectionHandler`, preserving the configured login cookie alongside the initialized `ttwid`. The original repository was unavailable during the earlier inspection; a preserved source copy was inspected at [KByteArray/ordinaryroad-live-chat-client, commit 6786f7906d5669fa8a5333354658e8daec00feba](https://github.com/KByteArray/ordinaryroad-live-chat-client/tree/6786f7906d5669fa8a5333354658e8daec00feba). `BilibiliAuthenticatedClient` preserves the same SDK transport and adds an original outbound authentication adapter for 1.5.8. Offline inspection of the SDK factory/encoder found omitted `platform`, `type=0` and body `protover=1`. The complete web-room authentication combination (`platform=web`, `type=2`, body `protover=2`, acknowledgement/scene/queue fields) was cross-checked against [AwooMusicBot commit cc9c3b7591677e8d98e0983a1f9c8d46fda51dbb](https://github.com/Enkianssus/AwooMusicBot/commit/cc9c3b7591677e8d98e0983a1f9c8d46fda51dbb), which documents the same missing-gift symptom. That repository's README declares MIT, but no standalone license text was found in the inspected tree; it is a protocol reference only and no source from it is copied or bundled. The adapter retains the SDK's existing room/token/device identifiers and uncompressed authentication frame header, and continues to use the existing zlib decoder. It does not treat `COMBO_SEND` cumulative hints as additional gift transactions.
